## 連載コンセプト

自宅 CPU の極小モデル(0.81M〜130M char-LM、一部 0.5B 既製モデルの CPU 変換)PoC を題材に、**大手 LLM の性能を直接競うのではなく、「手法・思想・計測規律」の次元で 2026 年 6 月の LLM 業界を読む**。全記事の共通土台は honest disclosure(負け・限界・未測・会計差を隠さず数字に刺す)。

### 共有バナー(全記事の冒頭に置く免責)

> 本連載の全 llcore 実測は、自宅 CPU の極小モデル PoC であり、大手の実 LLM(12B〜64B)の性能を直接反証・凌駕するものではない。比較は手法・思想・計測規律の次元で行う。

## アークの背骨(物語の流れ)

1. **計測規律の土台**(s1/s2/b1): 単一スコアは騙す → ベンチ拡大解釈の型 → だから負けを見せる。
2. **なぜこの土俵か**(b5): 賢さは CPU char-LM では構造的に negative → 北極星を memory 効率へ pivot。
3. **構造で勝つ**(a7→a8→a9): 理論(定数状態)→ 動的支配項(文脈長)→ 静的支配項(baseline)。「bit でなくアーキ/支配項を攻めろ」。
4. **honest disclosure の実例**(b3/b4/b7/b2): 会計差で AI 誤指摘を覆す → 安全 gate の空振り → 負けの道具を再配線 → NAS の勝利を自分で抑制。
5. **構築的な着地**(b6): 勝ち筋を検収可能な道具に畳む。
6. **普遍教訓**(a11): テストの難しさが設計を教える。
7. **技術の外の支配項**(c1/c2/c3): ライセンスが商用可否を決める(c1)→ 自己成長は両刃で止める機構が要る(c2)→ 記憶による一貫性はドメイン横断の普遍部品(c3)。エコシステム/戦略の軸で、honest disclosure(競合も自分も同じ刃で測る)を業界・他プロジェクトへ拡張。
